## 2026-06-25 — עיצוב-מחדש שיטת הציפים: זרימה רציפה (auto-flow) + רצף-פתיחה חדש
- **החלטה:** עיצוב-מחדש מלא של חוויית הציפים — להחזיר את המומנטום הרציף **בלי לוותר על מבנה-הציפים**:
  - **(A) Auto-flow ציפ-לציפ** (`LessonFlowScreen` seam): בסיום ציפ זורמים ישר לציפ הבא **בלי דֶטוּר למפה**; חוזרים למפה רק בציפ שחוצה את סף-התיבה. **גם אחרי התיבה** — מי שבוחר "להמשיך" זורם רציף עד 100% (post-chest auto-flow), לא דֶטוּר-לכל-ציפ. השינוי אדיטיבי: ההתנהגות לפני-התיבה/בחציה/ב-100% לא נגעה, רק ציפי post-chest זורמים מעכשיו.
  - **(B) אנרגיה כבויה ב-mod-0-1, פעילה מ-mod-0-1B** (`isEnergyEnabledForModule` ב-`useHeartsStore`). הסבר-אנרגיה חד-פעמי קופץ בסיום הציפ הראשון של mod-0-1B (`hasSeenEnergyIntro` ב-`useTutorialStore`).
  - **(C) רצף-פתיחה חדש (משתמש חדש):** אונבורדינג → חגיגת רצף-יום-1 → **נחיתה על המפה + הסיור (walkthrough) קופץ מיד** (במקום "אחרי הציפ הראשון") → תיבת-פתיחה → "המשך" **מתחיל אוטומטית את mod-0-1 רציף**. (`ProfilingFlow.enterFirstModule` מנווט ל-`/(tabs)`+`triggerWalkthrough`; `PostWalkthroughFirstChest` deep-link ל-lesson; הוסר טריגר-הסיור מ-`TopicTreeAccordion`).
  - **(D) Pro + הרשמה אחרי התיבה (chest → Pro → הרשמה):** הוסר חימוש ה-Pro/הרשמה מסיום-הסיור (`AppWalkthroughOverlay`); ה-Pro teaser מחומש כשנפתחת תיבת-mod-0-1 (`TopicTreeAccordion`), ולאורחים — סגירת ה-Pro teaser מחמשת את ה-CTA-הרשמה (`PostWalkthroughProTeaser`→`PostWalkthroughRegisterCTA`, השרשור הפוך). **מטפל ישירות בכשל-המונטיזציה "Pro נכשל ב-intent" (paywall קר post_walkthrough=0%).**
  - **(E) ספים נשמרים:** 50% ב-mod-0-1, 75% בשאר. שאלת `knowledgeLevel` נשארת מיד אחרי הקוויז, **לפני** התיבה — ה-auto-flow מריץ קוויז → שאלה → תיבה (ה-gate `mod01QuestionResolved` מכובד).
  - **(F) Game-feel:** קאלאוט "עוד X לתיבה" (pop+confetti) בין הציפים **לפני** התיבה בלבד · בר-התקדמות-לתיבה מקוטע בראש השיעור · **זהב+XP מעופפים** במסך-הבית בסיום 100% (בונוס 50+50 דרך `RewardAnimationProvider` שזיהוי-הדלתא שלו מנפיש אוטומטית) · **מחמאות קפטן שארק מגוונות** (חד-פעמי לא-חוזר, `moduleCompliments`, קול-יחיד-נטול-מין לפי BRAND.md) כשבוחרים להמשיך אחרי התיבה · הוחזרה הודעת "נשארה רק עוד דקה" בכפתור-חזרה אמצע-שיעור.
- **למה:** השלמת mod-0-1 צנחה מ-**~52%** (שיעורים רצופים, מאי) ל-**~37%** (ציפים, יוני) — כל ציפ החזיר למפה = נקודת-נשירה בכל גבול. הפתרון: זרימה רציפה (השורש), **בלי** להחזיר את ה"אוטופיילוט" הישן (ללא bar-מודולה / תיבת-summary-legacy). ראה אבחון 2026-06-19.
- **השערה / יעד נמדד:** השלמת mod-0-1 ב-**`chest_opened` (unique)** — לא `lesson_completed` — חוזרת לכיוון **~50%** (מ-~37%); ירידה בנשירות-הגבול בין הציפים; activation (intro→first-step) ↑; conversion Pro/הרשמה ↑ (תזמון אחרי-ערך). dashboards: PMF (763997) + מטריקת chest_opened.
- **סטטוס:** ⏳ מוזג ל-master (`8b9e4c1e`), ממתין ל-OTA + בילד (פקודות נמסרו ליואב). tsc-נקי בכל הקבצים שנגעתי. ⚠️ **לא נבדק על מכשיר** — מסלול-משתמש-חדש קריטי, מומלץ smoke-test אחרי ה-OTA (ניתן לרולבק). נדחף באותו מיזוג גם עבודת-לייב של סוכן אחר (`shark-voice-chat/*`) עם שגיאות-tsc פתוחות שלו.
- **תוצאה:** _(ימולא ~7–14 יום אחרי OTA — `chest_opened{mod-0-1}` unique לפני/אחרי + נשירות-גבול)_

## 2026-06-22 — סף תיבה 75% + קוויז ממוקם (לא חובה) + "תיבה ראשונה" אמיתי
- **החלטה:** (A) **סף פתיחת התיבה 70%→75%** (`TOPIC_COMPLETION_THRESHOLD`). (B) **ביטול חיוב הקוויז** כתנאי לתיבה (מחליף את gate ה-2026-06-17) — במקומו `topicResolver` **מקבע את צ'יפ הקוויז בתוך חלון-הסף** (75% / 50% ב-mod-0-1) כך שבמסלול הקנוני ("המשך") הקוויז מגיע לפני התיבה. (C) **רק mod-0-1** נשאר 50% (mod-0-2 חזר ל-default 75%). (D) **"התיבה הראשונה שלכם"** נגזר עכשיו מ-`modulesPastThreshold` (האם נפתחה כבר תיבה בכלל), לא ממזהה המודולה. (E) bugfix: כרטיס "תמחור המציאות" (price-slider) ב-`topic-game` host עטוף ב-ScrollView (flexGrow+center) — לא חורג מהתחתית.
- **למה:** יואב — הקוויז ירד בסוף הסדר, אז התיבה (70% + gate קוויז) נפתחה *אחרי* שהמשתמש כבר עבר 70% אבל בלי הקוויז → או חסימה מבלבלת או "עוד רכיב אחד והתיבה!" שלא קרה. הפתרון: לא לחייב, רק למקם מוקדם + סף 75%. בנוסף, "התיבה הראשונה שלכם" הופיע גם למי שכבר פתח תיבות (תלוי במזהה מודולה).

## 2026-06-19 — אבחון הפעלה: כניסה + סיום mod-0-1 (השיעור הראשון)
- **שאלה:** מה יגרום ליותר אנשים להיכנס למודולה 0-1 ולסיים אותה?
- **דאטה (PostHog, 30 ימים, `filterTestAccounts`):** משפך `onboarding_started`→`onboarding_completed`→`lesson_started{mod-0-1}`→`lesson_completed{mod-0-1}`:
  - started **1,510** → completed **981** (**−35%**) → נכנס mod-0-1 **915** (=**93%** מהמסיימים — הכניסה **לא** הבעיה) → סיים mod-0-1 **496** (=**54% מהנכנסים בלבד; −49%**).
  - end-to-end: רק **33%** ממתחילי onboarding מסיימים את mod-0-1.
  - מתוך ~419 שננטשו בתוך mod-0-1, רק **19** ירו `lesson_exited_early` מפורש — מתרכז ב-**phase הפותח** (`flashcards`=10 / `sim`=5 / `interactive-recall`=3 / `quizzes`=1). השאר = נטישה שקטה (רקע/סגירה). זמן-סיום **חציוני** למי שמסיים: **2:54 דק**.
- **מסקנה:** "כניסה" כבר פתורה (93%). שני מנופים: **(1) upstream** — להעלות כמה בכלל מגיעים = לתקן את **−35% ה-onboarding** (מסך-ראשון + signup-gate). **(2) completion** — חצי מהנכנסים לא מסיימים = הדליפה הגדולה ביותר (419/חודש). הפתיח הפסיבי (`flashcards`) מאבד אנשים **לפני** הניצחון הראשון.
- **מנופים מומלצים (completion, לפי ROI):** (א) **First-win מהיר** — לפתוח את mod-0-1 בשאלה/אינטראקציה winnable במקום flashcards פסיביים (חוק Brawl Stars: ניצחון תוך 30 שנ׳). (ב) אנרגיה 5→20 (כבר נשלח) מסיר קיר out-of-energy. (ג) resume + נדנוד חזרה (כרטיס-אתגר+streak שנשלחו) — חלק מסיימים בסשן מאוחר. (ד) סים קליל/אופציונלי בשיעור הראשון.
- **השערה / יעד נמדד:** `lesson_started`→`lesson_completed{mod-0-1}` **54%→70%**; end-to-end started→mod-0-1-done **33%→45%**.
- **סטטוס:** 📊 baseline נמדד (2026-06-19). ⏸️ ממתין להחלטה איזה מנוף לבצע ראשון (המלצה: א׳ — היפוך סדר, ניצחון לפני קריאה).
